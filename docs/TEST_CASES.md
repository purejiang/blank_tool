# Blank Tool 应用测试用例

**版本**: v2.1.3+
**更新日期**: 2026-07-22
**覆盖范围**: 任务管理 / 设备管理 / APK 工具 / 设置 / 跨切面

## 优先级说明

- **P0 (阻塞)**: 发版前必须全过；失败即阻塞发版
- **P1 (关键)**: 核心用户路径；失败需当班修复
- **P2 (一般)**: 次要功能或边界场景
- **P3 (补充)**: 视觉/体验类

---

## 一、任务管理（P0 — 最近修复区域，重点回归）

### TC-1.1 URL 下载 → 分析（最核心路径）

**前置条件**:
- 已连接网络
- 准备一个可公开访问的 APK URL（如 `https://example.com/test.apk`）

**步骤**:
1. 进入「APK 处理」页面
2. 源选择「URL」
3. 粘贴 APK URL
4. 操作选择「分析」
5. 点击「开始」
6. 等待任务完成

**预期**:
- 任务卡片出现，状态 `downloading` → `running` → `completed`
- 进度条从 0 平滑推进到 100%
- 下载完成后日志显示 `已完成 (X.XMB)`
- 分析完成后显示完整分析卡片：应用名、包名、版本、SDK、权限、架构、压缩分析、16KB 支持、Meta Data

**优先级**: P0

---

### TC-1.2 URL 下载中途切换页面（核心 bug 回归）

**前置条件**: 同 TC-1.1

**步骤**:
1. 按 TC-1.1 启动 URL 分析任务
2. **下载进行中**（进度 30-50%），点击侧栏切到「设置」
3. 等 5 秒
4. 切回「APK 处理」

**预期**:
- 切回后任务卡片仍在列表中
- 进度数字可能短暂不动（切换期间 progress 事件可丢），但状态不卡死
- 任务最终能到达 `completed`，分析数据完整展示
- **没有"loading 转圈但任务不动"的现象**

**优先级**: P0

---

### TC-1.3 操作阶段中途切换页面（核心 bug 回归）

**前置条件**: 准备一个本地 APK 文件（10MB+）

**步骤**:
1. 源选择「本地」→ 选择 APK 文件
2. 操作选择「反编译」（耗时较长，便于测试）
3. 点击「开始」
4. 状态变为 `running` 后，立即切到「关于」
5. 等任务执行（10-30 秒）
6. 切回「APK 处理」

**预期**:
- 任务状态正确显示 `completed`
- `outputPath` 字段指向反编译输出目录
- 日志区域有完整的反编译过程日志
- 点「在文件夹中查看」能打开输出目录

**优先级**: P0

---

### TC-1.4 分析任务切换页面后结果展示（刚修复的 bug）

**前置条件**: 准备本地 APK 文件

**步骤**:
1. 源选择「本地」→ 选择 APK
2. 操作选择「分析」
3. 点击「开始」
4. 状态 `running` 后切到「设置」
5. 等 10 秒（确保任务完成）
6. 切回「APK 处理」

**预期**:
- 任务状态 `completed`
- **完整分析卡片正确渲染**（应用名、包名、版本、权限、架构、压缩分析、16KB 支持等全部展示）
- 不只是空卡片或部分字段

**优先级**: P0

---

### TC-1.5 重新编译切换页面后 outputPath 正确（刚修复的 bug）

**前置条件**: 准备一个已反编译的 APK 项目目录

**步骤**:
1. 源选择「本地」→ 选择反编译项目目录
2. 操作选择「重编译」
3. 点击「开始」
4. 切换到其他页面
5. 等任务完成
6. 切回

**预期**:
- 任务状态 `completed`
- `outputPath` 指向 `recompiled/*.apk`（不是空）
- 点「在文件夹中查看」能定位到新 APK

**优先级**: P0

---

### TC-1.6 重签名切换页面后 outputPath 正确（刚修复的 bug）

**前置条件**:
- 准备本地 APK
- 设置中已配置至少一个签名配置（keystore）

**步骤**:
1. 源选择「本地」→ 选择 APK
2. 操作选择「重签名」
3. 选择签名配置
4. 点击「开始」
5. 切换到其他页面
6. 等任务完成
7. 切回

**预期**:
- 任务状态 `completed`
- `outputPath` 指向 `*-signed.apk`（不是空）

**优先级**: P0

---

### TC-1.7 任务进行中取消

**前置条件**: 准备本地大 APK（50MB+）

**步骤**:
1. 启动反编译任务
2. 等 3 秒（任务进入 running）
3. 点击任务卡片的「取消」按钮
4. 确认对话框点「确认」
5. 观察状态变化

**预期**:
- 状态 `cancelling` → `cancelled`（≤ 5 秒内）
- 日志末尾出现 `[time] 已取消`
- 反编译输出目录被清理（如果已生成）
- 取消按钮消失，重试按钮出现

**优先级**: P0

---

### TC-1.8 失败任务重试

**前置条件**: 无

**步骤**:
1. 源选择「URL」→ 填一个**无效 URL**（如 `https://example.com/notfound.apk`）
2. 操作「分析」
3. 点击「开始」
4. 等任务失败
5. 点击「重试」
6. 立即切到其他页面
7. 修改 URL 为有效地址（可选——看 UI 是否允许）
8. 切回

**预期**:
- 失败时显示错误通知 + 任务状态 `failed`
- 日志有错误原因（如 `404 Not Found`）
- 重试后任务重新进入 `queued` → `downloading`
- 重试不丢失原日志（有 `--- 重试 ---` 分隔）

**优先级**: P0

---

### TC-1.9 多任务并行

**步骤**:
1. 启动任务 A（URL 下载分析）
2. 任务 A 进行中，启动任务 B（本地 APK 反编译）
3. 观察两个任务卡片

**预期**:
- 两个任务独立显示，各自有进度条和状态
- 两个任务的日志互不串扰
- 取消 A 不影响 B

**优先级**: P1

---

### TC-1.10 任务历史持久化

**步骤**:
1. 启动并完成若干任务（含成功/失败/取消各一）
2. 关闭应用
3. 重新打开

**预期**:
- 终态任务（completed/failed/cancelled）仍在列表中
- 日志可点击「查看完整日志」加载
- 运行中任务**不持久化**（重启后消失——这是设计行为）

**优先级**: P1

---

### TC-1.11 清除已完成任务

**步骤**:
1. 列表中有 3+ 终态任务
2. 点击「清除已完成」
3. 确认对话框

**预期**:
- 仅终态任务被清除
- 运行中任务保留
- 设置开启「自动删除输出」时，对应输出目录也被删除

**优先级**: P1

## 二、设备管理（P1）

### TC-2.1 设备列表刷新

**前置条件**: 通过 USB 连接一台开启 USB 调试的 Android 设备

**步骤**:
1. 进入「设备」页面
2. 观察设备列表
3. 拔掉 USB，观察
4. 重新插上，点「刷新」

**预期**:
- 设备出现，状态 `device`（不是 `unauthorized`/`offline`）
- 拔掉后列表自动更新或点刷新后消失
- 重新插上后再次出现

**优先级**: P1

---

### TC-2.2 ADB TCP/IP 无线连接

**步骤**:
1. USB 连接设备
2. 在设备页输入设备 IP + 端口（如 5555）
3. 点击「连接」
4. 拔掉 USB
5. 观察设备是否仍在线

**预期**:
- 无线连接成功
- 拔掉 USB 后设备仍通过 WiFi 列出
- 能继续执行安装/shell 等操作

**优先级**: P1

---

### TC-2.3 安装 APK 到设备

**前置条件**: 设备已连接

**步骤**:
1. 在设备页选择设备
2. 选择本地 APK
3. 点击「安装」
4. 等待完成

**预期**:
- 进度显示安装过程
- 成功提示，设备应用列表出现该应用
- 失败时错误信息明确（如 `INSTALL_FAILED_VERIFICATION_FAILURE`）

**优先级**: P1

---

### TC-2.4 Logcat 实时输出

**前置条件**: 设备已连接

**步骤**:
1. 选择设备
2. 点击「Logcat」
3. 观察输出 10 秒
4. 点击「停止」

**预期**:
- 实时日志滚动显示
- 不同级别（I/W/E）有视觉区分
- 停止后不再更新，但已加载内容可滚动查看

**优先级**: P1

---

### TC-2.5 设备重启到 Bootloader/Recovery

**步骤**:
1. 选择已连接设备
2. 点击「重启」下拉
3. 选择「Bootloader」

**预期**:
- 设备重启进入 fastboot 模式
- 列表状态变化（可能变为 `fastboot` 或离线）

**优先级**: P2（谨慎测试，避免误操作生产设备）

## 三、APK 工具（P1）

### TC-3.1 APK 分析（本地文件）

**前置条件**: 准备本地 APK（建议包含 native 库，多架构）

**步骤**:
1. 源「本地」→ 选择 APK
2. 操作「分析」
3. 等待完成

**预期**:
- 基本信息：应用名、包名、版本、大小、SDK
- 架构 chips 正确标注（arm64/armeabi/x86_64）
- 权限按"危险/普通"分类
- 如有多架构，SO 对比卡片展示差异
- 如有 16KB 对齐检查，显示支持情况

**优先级**: P1

---

### TC-3.2 反编译带选项

**步骤**:
1. 选择 APK，操作「反编译」
2. **勾选「反编译资源」+ 不勾「反编译源码」**
3. 开始

**预期**:
- 输出目录有 `AndroidManifest.xml`、`res/`、`apktool.yml`
- **没有** `smali/` 目录（因为源码未勾选）
- 耗时比"两者都勾"短

**优先级**: P1

---

### TC-3.3 反编译 → 重编译 → 签名（端到端）

**步骤**:
1. 反编译 APK（资源 + 源码）
2. 反编译完成后，点新任务，源选「本地」→ 指向上一步输出目录
3. 操作「重编译」（选签名配置）
4. 等待完成
5. 把重编译后的 APK 安装到设备

**预期**:
- 重编译生成新的 APK
- 安装到设备能正常启动（签名有效）

**优先级**: P1

---

### TC-3.4 签名配置管理

**步骤**:
1. 进入「设置」→「签名配置」
2. 添加新配置：名称、keystore 路径、别名、密码
3. 保存
4. 关闭应用，重新打开
5. 在 APK 处理页操作「重签名」，确认下拉出现该配置

**预期**:
- 配置持久化
- 下拉列表显示
- 选中后能用该 keystore 完成签名

**优先级**: P1

## 五、跨切面（P2）

### TC-5.1 错误通知一致性

**步骤**:
1. 触发各类错误：
   - 无效 URL 下载
   - 不存在的本地路径
   - 设备未连接时安装
   - 无签名配置时重签名

**预期**:
- 每种错误都有右上角通知提示
- 任务卡片状态变 `failed` + 错误信息
- 日志末尾有失败原因

**优先级**: P2

---

### TC-5.2 系统通知（OS 级）

**前置条件**: 设置中开启「系统通知」

**步骤**:
1. 启动一个耗时任务（反编译）
2. **切换到其他应用**（让 Blank Tool 失焦）
3. 等任务完成

**预期**:
- 任务完成时 OS 通知弹出（如 "反编译 app.apk 已完成"）
- 点击通知聚焦回 Blank Tool

**优先级**: P2

---

### TC-5.3 应用重启后状态

**步骤**:
1. 启动 2 个任务（1 完成、1 运行中）
2. 有 1 个已签名的 APK 在输出目录
3. 关闭应用
4. 重开

**预期**:
- 已完成任务保留在列表
- 运行中任务**消失**（设计如此）
- 输出目录的文件还在
- 签名配置、主题、语言保留

**优先级**: P2

---

### TC-5.4 窗口缩放

**步骤**:
1. 拖拽窗口边缘缩放（最小 → 最大）
2. 折叠/展开侧栏
3. 在小窗口下操作任务

**预期**:
- 布局响应式，无溢出
- 任务卡片在小窗口下不换行错乱
- 日志区域可滚动

**优先级**: P3

## 附：已知限制（不算 bug）

- **运行中任务不持久化**：关闭应用即丢失（设计如此，后端无持久化）
- **apk/install 实时 log 不显示**：log 事件走 `logcat-output` 通道，是预存在 bug，不在本次修复范围；任务完成后可用「查看完整日志」读取磁盘日志
- **假进度条封顶 85%**：apk/install 后端不发真实 progress，UI 用模拟进度，最后 15% 由 complete 事件填满
- **分析时切换页面**：任务能完成，结果数据在 `transition` 之前生成的字段必须在 `transition` 之前处理好（已修复）
