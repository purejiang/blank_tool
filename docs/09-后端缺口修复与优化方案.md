## 1. 分类与结论

**不需要全部重做。** 16 项按性质分四类，真正"不做就卡住 UI"的只有 4 项：

| 类 | 含义 | 缺口 | 量级 |
|---|---|---|---|
| **A 阻塞 UI** | 不动后端/preload，对应界面做不出来 | #1 #2（文件读写通道）、#4（运行目录）、#11（历史状态字段） | 1–2 天 |
| **B 补字段/接口** | UI 骨架能做，细节缺 | #3 #13 #14（环境三件套）、#8（插件失败可见）、#16（uptime）、#12（模板 tags） | 2–3 天 |
| **C 口径与安全** | 影响正确性与数据安全 | #5（保留策略可配）、#6（清库误删模板/历史）、#15（通知默认值） | 1–2 天 |
| **D 契约清理** | 纯 TS 类型 / 后端语义一致性 | #9（protocol.ts 类型错）、#7（弱失败返回 `{error}` 不抛错） | 0.5–1 天 |
| **E 不改/延后** | 需改数据模型、收益低 | #10（节点 `timeout`、坐标持久化、`Port.default`） | 0（仅顺手修 `subtype` 丢失） |

A + B 是**在现有 handler/registry 上做加法**（单项 5–40 行），不是重写；C 是两处配置 + 一处数据安全；D 是类型对齐；E 明确不做，登记进 [06-后续路线图](./06-后续路线图.md)。

## 4. 工作包详细方案

### WP0 · 契约与类型清理（#9、#7）——无依赖，最先做

**为什么先做**：`protocol.ts` 的类型错会让每个新列表页拿到 `undefined`；弱失败语义会让 UI 把失败当成功。不修，后面所有页面都建在错地基上。

**改动文件**

1. `src/shared/ipc/protocol.ts` 修正类型（键集合不变，因此 `shared-contracts.test.mjs` 的 100% 覆盖断言不受影响）：
   - `app.info`：`AppInfo{packageName,versionName,installTime}` → `{ version: string }`（后端只回 `version`）。
   - `TaskListItem` → `{ run_id: string; task_id: string; cancelled: boolean; started_at: number | null; has_process: boolean }`（删掉后端不返回的 `type`）。
   - `template.list` → `{ templates: TemplateInfo[] }`；`TemplateInfo = { name; description; created_at; updated_at; tags: string[]; node_count: number }`。
   - `workflow.list_tools` → `{ tools: ToolEntry[] }`；新增 `PortJson{name,type:{base,subtype},required,description,options,multi,direction}`、`OperationJson{name,description,inputs,outputs}`、`ToolEntry{name,kind,is_valid,version,tool_path,builtin?,description?,ports?,operations?,env_deps?}`。
   - `workflow.list_envs` / `env.list` → `{ environments: EnvEntry[] }`；`EnvEntry{name,display_name?,type?,is_valid,binary_path,version,root_path,env_var_override?,path_override?,source?}`。
   - `history.list` → `{ runs: RunSummary[] }`；`history.get` → `{ run: RunRecord }`；`RunSummary{run_id,task_id,workflow_name,source,started_at,ended_at,duration_ms,success,error,status?,cancelled?,run_dir?}`；`RunRecord = RunSummary & {inputs, node_results}`。
   - `plugin.list/add/delete` → `{ plugins: PluginEntry[] }`；`PluginEntry{module,kind,version,loaded,error,source?}`。
   - `tool.get_tools`：单工具与全量两种返回拆成 `ToolStatusEntry` / `Record<string, ToolStatusEntry>`（现在是一个错误的联合类型）。
   - 追加 `'health': { params: Record<string, never>; result: { status: string; uptime_s: number } }`（TS-only key，契约测试只 warning）。
2. `src/shared/ipc/electronApi.ts`：把散在 index signature 里的方法显式列进 `ElectronApi` —— `onStreamEvent(cb) => () => void`、`selectFile`、`selectDirectory`、`showSave`、`readTextFile`、`writeTextFile`、`openPath`、`showSystemNotification`。
3. **弱失败改造**（#7）：把下列返回 `{"error": ...}` 的路径改为 `raise ToolException(...)`，与 `template.import_path`、`plugin.add` 现有语义对齐：
   - `cli/app/handlers/env_handler.py`：`handle_env_add` / `handle_env_delete` 的 `except (ValueError, OSError)` 分支。
   - `cli/app/handlers/tool_handler.py`：`handle_tool_add` / `handle_tool_delete` 的 `except ValueError` 分支。
   - `cli/app/tools/tool_manager.py::import_descriptor_dir`：`not a directory` 与 `no *.json descriptors found` 两个**顶层 error** 分支。
   - `tool.import_pack` 的**两阶段导入报告**保留不动（批量结果不是错误）。
4. 连带更新：
   - `tests/contracts/test_env_handler.py:133` → `pytest.raises(ToolException, match=...)`。
   - `tests/cli/unit/tools/test_import_pack.py:126` → 同。
   - `cli/cli.py:446` 的 `if "error" in report` 分支随之变死代码，清理并保留异常路径的 stderr + 退出码 1（`test_cli.py:533` 期望退出码 1，行为不变）。

**验收**：`npm run lint`、`node --test tests/shared-contracts.test.mjs`、`pytest tests/contracts/ tests/cli/` 全绿；渲染层 `await callBackendAPI('template.list')` 拿到的运行时形状与类型一致。

### WP1 · 主进程文件读写通道（#1、#2）——S1「导出」的唯一前置

**改动文件**

1. `src/shared/ipc/channels.ts`：新增 `showSaveDialog: 'show-save-dialog'`、`writeTextFile: 'write-text-file'`、`readTextFile: 'read-text-file'`。
2. `src/main/ipc/electronHandlers.ts`：新增三个 `ipcMain.handle`（写法对齐现有 `showOpenDialog` / `getFileStats` —— 取 `BrowserWindow.fromWebContents(event.sender)`，失败不抛、返回结构化结果）：
   - `show-save-dialog(options) → { canceled: boolean; filePath?: string }`，options 透传 `defaultPath` / `filters`。
   - `write-text-file({ path, content }) → { success: boolean; error?: string }`：先 `fs.mkdir(path.dirname(p), { recursive: true })`，UTF-8 写入；建议 tmp 文件 + `fs.rename` 原子落盘。
   - `read-text-file({ path, maxBytes? }) → { success: boolean; content?: string; error?: string }`：`maxBytes` 默认 **8 MiB**，`fs.stat` 超限直接返回 `{success:false, error:'file too large'}`；UTF-8 读取。
3. `src/preload/electron/dialog.ts` 加 `showSave`；`src/preload/electron/fs.ts` 加 `writeTextFile` / `readTextFile`（走 `ipcInvoke`，与 `getFileStats` 同款）；`src/preload/index.ts` 已 `...spread`，无需改。
4. `src/shared/ipc/electronApi.ts` 补类型（属 WP0）。

**安全边界（必须写进实现与文档）**：这三条通道让渲染层可读写任意路径，与既有 `openPath` / `selectFile` 处于同一信任模型（`AGENTS.md`「安全边界」已声明本应用是自用桌面工具、不可分发给不信任用户）。`maxBytes` 是防误读大文件，**不是**安全边界；本方案**不**引入额外沙箱或路径白名单。

**测试**：新增 `tests/unit/main/fileChannels.test.ts`（vitest + fs/dialog 桩）覆盖：写后读回、父目录自动创建、超 `maxBytes` 被拒、取消返回、错误路径返回 `{success:false}`。

**验收**：渲染层 `await window.electronAPI.writeTextFile(p, JSON.stringify(def))` 后文件存在且内容正确；S1「导出」可交付。

### WP3 · 工具与环境闭环（#3、#13、#14、#8）

1. **#3 环境字段**：

**测试**：`tests/contracts/test_env_handler.py`（新字段 + set_path/reset_path + 内置环境拒绝删除）、`tests/cli/unit/env/test_registry.py`（覆盖优先级 `env_paths` > runtime > 系统变量 > PATH，且 `refresh()` 后生效）、`tests/contracts/test_plugin_handler.py`（失败插件出现在 list 且带 error）、`tests/contracts/test_workflow_contracts.py`（`env_deps` 出现在 `list_tools`）。

### WP6 · 顺手修 / 明确不做（#10）

- **顺手修**（可并入 WP0）：`src/renderer/components/workflow/ioAuthoring.ts::portFromDraft` 会丢 `type.subtype` → 编辑端口时保留原 subtype（1 行级修复 + 现有 `tests/unit/workflow-editor/ioAuthoring.test.ts` 加断言）。
- **明确延后**（登记进 [06-后续路线图](./06-后续路线图.md)，UI 不承诺）：
  - **节点级 `timeout`**：需 definition schema + 引擎 + 序列化三方改动；现有替代是工具操作级 `timeout` 与 CLI 整轮 `run --timeout`。
  - **节点坐标持久化**：会改 `WorkflowDefinition` 或引入 sidecar 文件；收益低，UI 不承诺"布局保持"。
  - **`Port.default`**：需端口 schema + 校验 + 表单预填；暂用工作流 `description` 说明默认值。

## 5. 建议执行顺序与并行度

```
WP0（类型 + 弱失败）
 ├─ WP1（文件通道）──────────► 可交付：S1 导入/导出
 ├─ WP2（run_dir/历史状态/uptime）► 可交付：S1 徽章、S4 筛选、S5 详情
 └─ WP5（模板 meta）─────────► 可交付：S2 标签编辑
WP3（环境/插件）  ──► 可交付：S6 三 tab 完整
WP4（配置/安全）  ──► 可交付：S7 存储与保留策略、系统通知默认关
WP6（subtype 修复 + 路线图登记）
```

- WP1 / WP2 / WP5 之间无耦合，可并行。
- WP3 依赖 WP0 的 `EnvEntry` 类型定义。
- WP4 独立，可与 WP3 并行。

## 6. 质量门禁与硬约束

| 命令 | 覆盖 |
|---|---|
| `npm run lint` | `vue-tsc` 类型检查 |
| `npm run test` | `tests/unit/**`、`tests/integration/**`（vitest） |

**硬约束（写给实现方）**

- 后端**仅用 Python 标准库**，不新增 `requirements.txt` 依赖。
- 改 IPC 通道名 → 必须同步 `tests/shared-contracts.test.mjs`；**新增**通道不需要。
- 新增/修改后端 handler 方法 → 必须同步 `src/shared/ipc/protocol.ts` 的 `ApiMethodMap`（契约测试断言 100% 覆盖）。
- 不改 `docs/07` 的 8 条已批准 Stitch 提示词；新增 UI 文案必须同时进 `zh-CN.ts` + `en-US.ts`。
- 颜色只用 `--app-*` 变量；不引入 Android 专属界面措辞。
- TS 非严格模式：新增代码写严格些，但**不要**大面积重构老代码。

## 7. 风险与取舍

| 风险 | 缓解 |
|---|---|
| WP0 把 `env.add` / `tool.add` 改成抛错，会动 2 个测试与 `cli.py` 一处分支 | 与 `template.import_path`、`plugin.add` 的既有语义对齐，一次性改完，不保留双语义 |
| WP4 的 `storage.clear` 是**行为变更**（原本会删模板/历史） | 默认更安全 + `include_managed: true` 逃生开关；08 缺口 #6 与本文档同步标注"已修" |
| WP4 改通知默认值影响老用户观感 | 走 v6→v7 迁移显式翻转，并在发版说明里写明 |
| WP3 环境路径覆盖与缓存不一致 | 覆盖变更后强制 `refresh()`；单测锁定 4 级顺序；同步 `docs/03` 第 9 节 |
| 新增三条文件通道扩大渲染层能力面 | 与既有信任模型一致；在本文档第 4 节 WP1 显式声明，不承诺沙箱 |
| WP5 若选 `template.meta`，需同步 `ApiMethodMap` | 首选"扩展 `template.load` 返回"这一纯附加方案，避免新增方法 |
