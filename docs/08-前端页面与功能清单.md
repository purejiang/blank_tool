>
> 与 [07-UI设计规范](./07-UI设计规范.md) 的分工：**07 管视觉与设计产出流程**（Google Stitch 提示词、外壳冻结契约、交接验收）；**08 管逐屏功能、字段、数据来源与状态**（哪个元素点下去调用哪个后端方法、空态长什么样、哪些能力现在做不了）。视觉以 07 里用户确认的设计稿为准，功能元素以本文档第 3 节为准，**功能元素不可删减**。

## 1. 范围与用法

- **本文档做什么**：定义重构后需要哪些屏幕、每屏包含哪些功能元素、每个元素绑定哪个后端方法、有哪些状态与边界，以及**哪些东西现在做不了**（第 7 节）。
- **本文档不做什么**：不定视觉（07 定）、不排期（[05-分期开发计划](./05-分期开发计划.md) 定）、不含实现代码。
- **怎么用**：
  1. 做 UI 设计/AI 生成时，读第 2 节（外壳）+ 第 3 节（目标屏）+ 第 8 节（逐屏提示词）；
  2. 做前端实现时，读第 3 节（功能 + API 绑定）+ 第 5 节（跨屏约定）+ 第 7 节（缺口，先改后端/preload 再实现 UI）；
  3. 验收时用第 9 节清单逐项勾。

## 2. 信息架构与外壳

### 2.1 一级模块（冻结）

| 模块 | 路由 | 页面 |
|---|---|---|
| 工作流 | `/workflows` | 工作流列表 |
| 工作流 | `/workflows/editor/:name?` | 工作流编辑器（二级页，从列表进入） |
| 任务 | `/tasks` | 任务中心（`?tab=new` 为「新建任务」，默认 tab 为「历史」） |
| 工具 | `/tools` | 工具与环境（`?tab=tools` 默认 / `?tab=env` / `?tab=plugins`） |
| 设置 | `/settings` | 设置（含「关于」块与诊断/关于入口） |

- `/` 重定向到 `/workflows`。
- 二级路由（**不进侧边栏**，从一级页进入）：`/about`（关于，内容等同 S7 的「关于」块，二者只保留一个入口）、`/diagnostics`（诊断，即 S8）。
- 退役边界：界面中**不得出现任何 Android 专属入口或措辞**（设备管理、APK 一键操作、签名配置等，也**不在界面文案里点名 `examples/**/android` 子目录**）。Android 能力只存在于用户自行导入的 `examples/` 内容里，执行路径与其他工作流完全一致。

### 2.2 外壳元素

| 元素 | 内容 | 状态 |
|---|---|---|
| 左侧边栏（窄） | 顶部应用名 `Blank Tool`（+ 折叠按钮）；中部 4 个带图标导航项（工作流 / 任务 / 工具 / 设置）；底部主题切换 | 折叠态 64px，展开 220px（沿用现实现） |
| 侧边栏页脚 | 后端健康点 + `v<前端版本> \| backend <后端版本>` | 复用现有 `StatusBar` |
| 内容区 | 页面标题 + 一句话描述 + 内容 | 每屏统一 |
| 全局加载屏 | 步骤文案（服务 → 配置 → 工具探测 → 准备界面）+ 进度 + 耗时 + 失败重试（≤3 次） | 已有 `LoadingScreen` |
| 全局容器 | 退出确认、更新对话框、应用内通知（toast） | 已有 |
| 全局横幅 | 后端不可用 / 初始化降级提示 | 需补 |

## 3. 屏幕清单

每屏给出：**目的 / 布局分区 / 功能元素 / 数据来源 / 状态 / 边界与现状差距**。

### S0 启动加载屏

- **元素**：应用名、进度条、当前步骤文案、已耗时秒数、失败态文案 + 「重试」/「重新加载」。
- **数据**：`registerServices` → `appConfig` / `system.info` / `build.info` → 工具探测（`tool.get_tools`）→ 主题/语言/更新/任务流订阅。
- **状态**：加载中 / 失败（可重试，超 3 次禁用重试）/ 完成。
- **现状**：已实现，微调文案与视觉即可。

### S1 工作流列表 `/workflows`

- **目的**：管理工作流模板（下称"工作流"）——新建、导入、导出、试运行、改名、复制、删除、搜索。
- **布局**：页面头（标题 + 描述）→ 工具栏 → 卡片网格 / 空态。
- **工具栏元素**：
  | 元素 | 行为 | 数据 |
  |---|---|---|
  | 「新建工作流」主按钮 | 跳 `/workflows/editor`（空定义） | — |
  | 「导入」 | 文件多选或目录选择 → 导入并出结果报告（M2） | `selectFile` / `selectDirectory` + `template.import_path {path}` |
  | 「导出」 | 需先选中卡片：加载定义 → 写 JSON 到用户选定路径 | `template.load` +（**待补** 保存对话框，见缺口 #1） |
  | 搜索框 | 按 `name` / `description` / `tags` 前端过滤 | — |
  | 刷新 | 重新拉列表 | `template.list` |
- **卡片元素**（数据源 `template.list`：`name` / `description` / `created_at` / `updated_at` / `tags` / `node_count`）：
  - 名称、一句话描述（可为空则显示占位）
  - meta：`节点数 {node_count}`、`最近更新 {updated_at}`
  - 标签 chips（`tags`，为空则不显示）
  - **上次运行状态徽章**：用 `history.list` 按 `workflow_name` 匹配最新一条，取 `success` / `duration_ms` / `ended_at`；无记录显示"未运行"。⚠️ `history.list` 的摘要**不含** `status` / `cancelled`（见缺口 #11），所以只能区分"成功 / 未成功"，**区分不出"失败"与"已取消"** —— 徽章文案要么只写「上次未成功」，要么改用 `history.get` 逐条取完整记录（列表页不建议）。
  - `⋯` 菜单：编辑 / 复制 / 试运行 / 导出 / 重命名 / 删除
- **交互**：
  - 点击卡片 → 进入编辑器（`/workflows/editor/<name>`）
  - 复制 = `template.load` + `template.save`（新名称，重名先确认）
  - 试运行 = 打开 M1 输入表单 → `template.execute {name, inputs}`
  - 重命名 = `template.load` + `template.save`（新名）+ `template.delete`（旧名）
  - 删除 = 确认弹层（M4）→ `template.delete {name}`
- **空态**：无工作流时居中引导，两个按钮：「导入示例工作流」（文件多选或目录选择，说明文案写"仓库 `examples/workflows/generic` 的示例零依赖、导入即跑；`examples/workflows/` 下另有需先导入工具描述符才能跑的示例"）/「新建工作流」。**界面文案不点名 `android` 目录**（退役边界，见 §2.1）；需要精确路径时放在文档/日志提示里。
- **状态**：加载中（骨架卡片）/ 空 / 有数据 / 加载失败（可重试）/ 后端不可用横幅。
- **边界与差距**：
  - `template.list` **不含**上次运行信息，必须与 `history.list` join；`history.list` 默认只取 50 条，工作流多时徽章可能缺失 → 文案弱化为"最近一次"或不显示。
  - `tags` 目前只在 `template.save` 时写入，编辑器需补标签编辑（见 S2），否则筛选与 chips 长期为空。

### S2 工作流编辑器 `/workflows/editor/:name?`

- **目的**：画布式编排线性工作流，配置节点与工作流级出入参，试运行并观察节点实时状态。
- **布局**：顶栏 → 左栏工具面板 / 中间画布 / 右栏节点配置（未选中节点时不显示右栏）。
- **顶栏元素**：
  | 元素 | 行为 | 数据 |
  |---|---|---|
  | 返回 | 回 `/workflows`（有未保存改动先确认） | — |
  | **工作流名（可编辑）** | 直接改 `definition.name`；另可编辑 `description` / `tags` | 现状 `meta.name` 不可编辑，**需新增**；⚠️ `tags` 只存在于模板包装元数据、**只有 `template.list` 能读到**（`template.load` 只回 `{definition}`，而 `WorkflowDefinition` 无 tags 字段）→ 见缺口 #12 |
  | 保存 / 另存为 | 保存对话框（名称 / 描述 / 标签，重名即覆盖，需确认） | `template.save {name, definition, description, tags}` |
  | 试运行（主按钮） | 打开 M1 输入表单 → 执行 | `workflow.execute {definition, inputs}` |
  | 运行中：取消 | 终止正在跑的节点与子进程 | `request.cancel {task_id}`（现状无取消 UI） |
  | 问题面板开关 | 展示静态校验结果，warning 不阻断 | `workflow.validate {definition}`（现状未接入） |
- **左栏 工具面板**（`workflow.list_tools`）：
  - 分组：内置（`kind = shipped-native`）/ 插件（`native`）/ 已导入描述符（`descriptor`）
  - 条目：名称、有效性点（`is_valid`）、一句话描述（`description`，缺失时回退为端口数量）、拖拽手柄
  - **搜索框**（现状无）与**点击追加到链尾**（现状只能拖拽）
  - `is_valid = false` 的条目需明确降级：视觉变灰 + 禁用拖拽 + tooltip 说明（现状变灰但仍可拖拽）
- **画布**（@vue-flow）：
  - 点阵背景、缩放控件、小地图、适配视图
  - 节点卡片：图标、节点名、工具名/操作名、状态标记、输入端口（左侧 handle）/ 输出端口（右侧 handle）、必填标星
  - 节点状态：`idle` / `running`（脉冲环）/ `ok`（✓）/ `failed`（✗）/ `skipped` / `cancelled`
  - 连线：拖拽连接，类型不兼容时禁止并提示（按端口 `base` 比较，`subtype` 仅建议性）
  - 节点操作：选中、`Delete` 删除、右键菜单（删除 / 复制节点 / 在其后插入）、拖动排序
  - 空态提示（**需 i18n**，现状英文硬编码）
- **右栏 节点配置**：
  - 工具名 + 工具描述
  - **操作下拉**（`operations[]`，来自 `workflow.list_tools`）+ 操作描述；切换操作时清空已填参数并提示
  - **按操作渲染类型化参数表单**：`text` / `number` / `boolean` / 单选 / 多选 / `file` / `directory` / `json`；`file` / `directory` 带「浏览」按钮；`json` 用等宽 textarea + 解析校验
  - **表达式绑定展示与插入**：`$inputs.<key>`、`$nodes.<id>.outputs.<port>`、`$nodes.<id>.params.<key>`、`$env.<name>`、`$workdir`、`$rundir`；管道变换 `basename` / `dirname` / `default:<值>`；提供候选插入（chips 或下拉），现状仅纯文本输入
  - 校验提示：未选操作 / 缺失必填输入（列出端口名）/ 选择端口未定义 `options`
  - 节点级字段：`on_failure`（`fail` | `skip`）、`retry`（数字，旁边说明隐含退避 `min(2^(n-1), 30s)`）
  - 节点 `id` 可编辑（唯一性校验）
  - 只读输出端口列表（类型 + 名称 + 说明）
  - 底部：删除节点
- **工作流级出入参面板**（现 `IoAuthoringPanel`）：inputs / outputs 双 tab；行显示名称、类型、必填徽章、描述；编辑表单含名称（`snake_case` 校验）、8 种类型（文本 / 文件 / 目录 / 布尔 / 数字 / JSON / 单选 / 多选）、必填开关、描述、单选与多选的选项列表编辑器（增删 + 上下移）；同侧重名校验；跨侧允许同名。
- **执行反馈**：
  - 顶部 alert 横幅：成功 / 失败（显示 `error`）/ 已取消；发生新一次运行前保留
  - 节点状态实时更新：订阅 `stream-event` 的 5 类事件 —— `node_started{node_id, tool}`、`node_completed{node_id, status(ok|failed|skipped|cancelled), duration_ms, attempts, error?}`、`workflow_completed{success}`、`workflow_failed{error}`、`workflow_cancelled`；事件还带 `run_id` / `workflow_id` 用于过滤。⚠️ 取消时引擎**不发 `node_completed`**（直接返回取消结果），实时流里只会有 `workflow_cancelled` → 界面上"运行中被取消"要把进行中的节点统一切成 `cancelled`，不要等 `node_completed`；`cancelled` 这个节点状态只会出现在历史的 `node_results` 里。
  - **运行日志抽屉**：`task.read_log {task_id}`（`content` / `truncated` / `size` / `log_path`）+ 打开日志文件（`openPath`）
- **状态**：未保存改动标记、运行中（禁用重复运行、显示取消）、校验有 error、后端不可用。
- **边界与差距**：
  - **节点级超时不存在**（`WorkflowNode` 没有 timeout 字段，只有描述符操作级 `timeout`）→ 配置面板不提供该字段。
  - 无撤销/重做、无快捷键体系。
  - 节点坐标不持久化：重新加载总是重新堆叠 → 不要承诺"布局保持"。
  - 序列化只取每个节点的第一条出边为 `next`，多余出边被忽略（线性模型）；`type` 字段仅标签用途，界面不必暴露。

### S3 任务 · 新建任务（`/tasks?tab=new`）

- **目的**：选一个已保存工作流，按它的入参声明填表，执行并跳到进度视图。
- **布局**：左列模板选择器 / 右列动态表单 / 底部执行区。
- **元素**：
  - 左列：模板列表（`template.list`）+ 搜索 + 标签过滤；行显示名称、描述、节点数、更新时间；选中态高亮
  - 右列：按选中模板的 `definition.inputs` 生成表单 —— 需先 `template.load {name}` 拿端口定义
    | 端口类型 | 控件 |
    |---|---|
    | `text` | 单行输入（`type=textarea` 的说明用多行） |
    | `file` | 路径输入 + 「浏览」按钮（`selectFile`） |
    | `directory` | 路径输入 + 「浏览」按钮（`selectDirectory`） |
    | `number` | 数字输入 |
    | `boolean` | 开关 |
    | `json` | 等宽多行输入 + 解析校验 |
    | 单选（`options` 非空、`multi=false`） | 单选组 / 下拉 |
    | 多选（`options` 非空、`multi=true`） | 复选框组 |
  - 每个字段：必填标星、端口 `description` 作帮助文本；可选字段留空则不提交（不要把空串当值）
  - **工作目录 `work_dir`**（可选输入，留空则用模板库目录；后端已支持 `params.work_dir`，现状无入口）
  - 底部：「执行」主按钮；必填缺失时**阻止启动并逐字段标红提示**
- **空态**：无模板 → 引导去 `/workflows` 导入或新建。
- **执行后**：切到「历史」并自动展开本次运行，显示逐节点进度与日志，提供取消。
- **差距**：`Port` **没有 `default` 字段**，所以没有"默认值预填"能力。

### S4 任务 · 历史（`/tasks` 默认 tab）

- **目的**：查看全部运行记录，筛选、回看、取消、重跑、清理。
- **布局**：筛选栏 → 列表 → （行展开 → S5 运行详情）。
- **筛选栏**：名称搜索（匹配 `workflow_name` / `source` / `task_id`）、状态下拉（全部 / 运行中 / 成功 / 失败 / 已取消）、刷新。
- **列表行**：状态徽章 + 工作流名 `workflow_name` + 来源 `source` + 开始时间 `started_at` + 耗时 `duration_ms`。
  - 状态口径：`success = true` → 成功；`success = false` → 未成功。**摘要里没有 `status` / `cancelled`**（`history.list` 只投影 9 个字段），所以列表层**分不出"失败"与"已取消"**；`status`（`succeeded｜failed｜cancelled`）只在 `history.get` 的完整记录里。要么把这两个字段补进摘要（缺口 #11），要么列表只显示"成功 / 未成功"，把精确状态放在 S5 详情。
  - **运行中**不在历史里（历史只记终态），来自 `task.list` 的 `{run_id, task_id, cancelled, started_at, has_process}`，需合并展示
- **分页**：`history.list {limit, offset}`（默认 50，`0` = 不限）→ 「加载更多」
- **行操作**：取消（仅运行中，`request.cancel {task_id}`）/ 重新运行（用记录中的 `inputs` 复跑；`source = "inline"` 的记录没有模板名，需先另存为工作流或提示不可复跑）/ 打开运行目录 / 删除（`history.delete {run_id}`）/ 「清空全部」（`history.clear` + 二次确认）
- **空态**：无记录 → 引导「新建任务」。
- **边界与差距**：
  - **保留策略**：后端按 `server.config.json` 的 `history.{enabled, max_runs=200, max_bytes=200MB}` **自动裁剪**（每次写入后 `_prune`，`max_runs: 0` 等于立即裁剪但仍写盘）→ 本清单口径为"**按上限自动裁剪**"，界面需有说明文案，且目前**没有任何 API 能改这三项配置**（见缺口 #5）。⚠️ 这与 [05-分期开发计划](./05-分期开发计划.md) 里"历史全保留，仅手动删除，无自动清理"的旧口径冲突，以本文档与 07 为准，05 需同步。

### S5 运行详情（S4 行展开后的抽屉；可升级为 `/tasks/:runId` 二级页）

- **目的**：回答"这次为什么失败 / 每一步花了多久 / 输出了什么"。
- **数据**：`history.get {run_id}` → 完整记录 `{run_id, task_id, workflow_name, source, started_at, ended_at, duration_ms, inputs, node_results, success, status, cancelled, error}`
- **元素**：
  - 头部：状态徽章、`workflow_name`、`run_id`、`task_id`、起止时间、`duration_ms`
  - 输入快照：`inputs` 键值表；值为路径时提供「打开」（`openPath`）
  - 逐节点步骤：遍历 `node_results`（**以节点 id 为键的字典**），每项显示 `status`（`ok|failed|skipped|cancelled`）、`duration_ms`、`attempts`、`error`、`outputs`
    - `node_id` 是**相对运行根的路径**，形如 `loop/0/step`（`flow.foreach` / 分支 / 子工作流产生的嵌套）→ 建议按 `/` 分层缩进或树形展示
  - 节点输出：按端口名展示；**截断标记必须专门渲染** —— 被 `shrink_outputs` 裁过的值形如 `{"_truncated": true, "_chars": <原长度>, "_preview": <前若干字符>, "_reason"?: ...}`（阈值按**字符数**：单字符串 > 8×1024 字符、单次输出总量 > 256×1024 字符），不要当普通文本显示
  - 运行级 `outputs` / `error`
  - 日志区：`task.read_log {task_id, tail_bytes?}`（`content` / `truncated` / `size` / `log_path`）+ 「打开日志文件」+ 刷新
  - 操作：取消（运行中）/ 重新运行 / 打开运行目录 / 删除记录 / 删除产物（`task.delete_output {paths}`）
- **边界与差距**：
  - **运行目录路径没有任何 API 返回**：`workflow.execute` / `template.execute` 只返回 `{success, status, cancelled, outputs, node_results, error}`，`history.get` 也没有 `run_dir`。⚠️ 前端**无法自行推导**：运行目录是 `<output_dir>/runs/<slug>`，而 slug 是**渲染层本地生成的 JSON-RPC 请求 id**（不返回给渲染层），历史里的 `run_id` 又是后端另生成的 uuid4 —— 两者对不上。必须由后端在 execute 返回值或 `history.get` 里给出 `run_dir`（见缺口 #4）。
  - 历史里的 `run_id` 是后端新生成的 32 位 uuid4 hex，**不等于** IPC 请求 id；`task_id` 才是任务维度标识。
  - 历史里**没有进度字段**；进度只能来自运行中的实时事件，历史回看只能看终态。

### S6 工具与环境 `/tools`

三个 tab：**工具 | 环境 | 插件**。

#### S6.1 工具 tab

- **工具栏**：「导入工具包（目录）」/「导入描述符（单文件）」/ 刷新。
- **列表项**（需合并两个接口）：
  | 字段 | 来源 |
  |---|---|
  | `name` / `kind` / `is_valid` / `version` / `tool_path` / `description` / `ports` / `operations` | `workflow.list_tools` |
  | `source`（`system`｜`none`）/ `status`（`available`｜`unavailable`）/ `path` | `tool.get_tools`（可按 `refresh: true` 触发重新探测） |
  | 自定义路径覆盖 | `tool.get_custom_paths` |
- **卡片元素**：名称、描述、来源徽章（内置 / 已导入 / 插件）、版本、操作数、状态徽章（可用 / 不可用）、实际路径。
- **详情展开**：`ports.inputs` / `ports.outputs`（类型、必填、`options`、`direction: "output"` 的产物端口）、每个 `operations[]`（名称、描述、inputs、outputs）。⚠️ `env_deps` **两个工具接口都不返回**（只在描述符模型里）→ 要展示需后端补字段（见缺口 #14）。
- **操作**：配置自定义路径（`tool.set_custom_path {tool_name, path}` + 文件选择）、重置路径（`tool.reset_custom_path {tool_name}`）、删除（`tool.delete {name}`，内置禁删）、搜索系统 PATH 开关（`tool.set_search_mode {system_search}`）。
- **导入**：目录批量（`tool.import_pack {path}`，返回 `{ok, imported, updated, failed, results[]}`）；单文件（`tool.add {descriptor}`，需先读出文件内容 —— 见缺口 #2）。
- **空态**：无描述符工具 → 引导「从 `examples/tools/` 导入工具描述符」（界面文案不点名 `android` 子目录，理由同 S1）。
- **边界**：`tool.add` / `tool.delete` 失败时返回 `{"error": "..."}` 而**不是** reject → UI 必须检查 `error` 键，否则会把失败当成功。

#### S6.2 环境 tab

- **行元素**（`env.list` 或 `workflow.list_envs`，二者返回形状相同，**只选一个调用**）：环境名（Java / Python / Node）、检测到的二进制路径 `binary_path`、版本 `version`、状态徽章（`is_valid` → 已检测 / 未配置）、`root_path`。
- **操作**：刷新、**更改路径**（⚠️ **没有对应 API**：环境注册表只有 `add_descriptor` / `delete_descriptor`，没有 set-path；路径只能靠 `env_var_override` 环境变量或重新导入描述符覆盖 → 见缺口 #13）、导入自定义环境（`env.add {descriptor}`，收整份描述符 → 需要表单或 JSON 编辑器）、删除（`env.delete {name}`，内置环境受保护会返回 `error`）。
- **边界**：`env.list` **只返回** `{name, is_valid, binary_path, version, root_path}` —— 没有 `display_name` / `type` / `search_paths` / `env_var_override`，也无法区分内置与用户导入（见缺口 #3）。所以在后端补齐之前，显示名只能由 `name` 映射，删除按钮需允许失败并展示后端错误。
- **内置行标记**：受保护的环境（`cli/registry/environments/*.json`：java / python / node）删除会被拒；界面需据此前置禁用删除或在失败后给出可读原因。

#### S6.3 插件 tab

- **工具栏**：「添加插件」（`module` / `path` / `config` JSON）、「重载」（`plugin.reload`）、刷新（`plugin.list`）。
- **行元素**：`module`、kind 徽章（`shipped-native` 内置 / `native` 原生）、`version`、加载状态（`loaded` / `error`）。⚠️ `plugin.list` **不会**返回 `descriptor` 这一 kind（清单加载器只允许 `shipped-native` / `native`；描述符工具走 `tool.*`，见 S6.1），所以界面上只会有两种徽章。
- **操作**：删除（`plugin.delete {module}`，`shipped-native` 禁用）。
- **边界**：加载器不记录单个插件的导入失败，`loaded` 恒为 `true`、`error` 恒为 `""` → 界面**不能**承诺"加载失败"提示（见缺口 #8）。

### S7 设置 `/settings`

- **通用**：请求超时（默认 **300000 ms**，不是 30 秒）、系统通知开关（**产品要求默认关**；⚠️ 现状主进程配置 `appStore.ts` 的 `enableNotifications` 默认是 `true`，实现时需改默认值，见缺口 #15）、删除任务时清理输出文件。
- **外观**：浅色 / 深色 / 自动（靠 `data-theme` 属性，**不是** `prefers-color-scheme`）。
- **语言**：简体中文 / English（文案必须同时进 `zh-CN.ts` 与 `en-US.ts`）。
- **行为 / 日志**：日志级别（debug / info / warn / error）。
- **路径**：runtime / server / serverEntry / runtimeExecutable / output / logs —— 每行路径 + 「浏览」按钮（preload 侧是 `settings.getViewModel`、`settings.resolvePaths`，另有 `appConfig.set`）。
- **工具路径**：**收敛到 `/tools` 工具 tab**，设置页只留一个跳转链接，避免双入口（Phase 4 要求）。
- **存储**：`cache.info` 四块（tasks / output / logs 各自的 `path` / `size` / `files`，加 `total`）；每块可单独清除（`tasks.clear` / `output.clear` / `logs.clear`），另有「一键清除全部」（`storage.clear {target: "all"}`）。
  - ⚠️ **必须显著警示**：`output/` 目录里同时放着 `templates/`（已保存工作流）、`history/`（运行历史）、`runs/`（运行产物），"清除全部"会一并删除（见缺口 #6）。
- **高级**：历史保留策略（`enabled` / `max_runs` / `max_bytes`）—— 目前**没有任何 API 能读写 `server.config.json`**，只能只读展示（见缺口 #5）。
- **关于块**：应用版本 / Electron / Node / Python（`app.info` / `build.info` / `system.info`）+ 后端健康徽章（`get-backend-health`，仅探测进程存活）。
- **底部入口**：「诊断信息」→ `/diagnostics`；「关于」→ 弹窗（与 `/about` 二级路由同源同内容，二者只保留一个入口；03/02 中现有的 `/about` 页面内容即为该块）。

### S8 诊断 `/diagnostics`（只读）

- **后端健康**：健康 / 异常 / 未知、最后检查时间、**进程存活时长（前端计时）**。⚠️ 主进程 `get-backend-health` 只探测进程存活、`uptime_s` 恒为 `null`（唯一能给 uptime 的是后端 `health` 方法，但它不在 `ApiMethodMap` 且无调用方）→ 若必须显示真实 uptime，需先把 `health` 接入（见缺口 #16）。
- **运行中任务表**：`task.list` → `run_id` / `task_id` / `cancelled` / `started_at` / `has_process`，每行「取消」（`request.cancel`）。
- **日志尾部**：三个 tab —— 后端日志（`logs.tail {lines}`）、Electron 日志（`readElectronLogTail`）、渲染层日志（内存 ring buffer）；显示行数、`truncated` 标记、刷新。
- **解析后路径**：runtime / server。
- **边界**：健康检查只判断进程存活，进程活着但卡死时仍报"健康"；诊断页不做任何配置写入。

## 5. 跨屏约定

1. **主题**：三模式（浅色 / 深色 / 自动，靠 `data-theme`）都要支持；设计稿至少出**浅色 + 深色两态**（"自动"跟随系统，等价于浅或深）；颜色只用 `--app-*` 变量（新增色相 light/dark 两侧都加）；字体只用 `--app-font` / `--app-font-mono`。
2. **i18n**：所有文案进 `zh-CN.ts` + `en-US.ts`；顺带清理遗留 Android 文案（`task.*` 里的 APK/设备/签名区块）与未被引用的键。
3. **状态徽章语义**（全站统一）：

   | 语义 | 值 | 视觉 |
   |---|---|---|
   | 运行中 | `running` | 蓝色 + spinner |
   | 成功 | `ok` / `succeeded` / `success=true` | 绿色 ✓ |
   | 失败 | `failed` | 红色 ✗ |
   | 跳过 | `skipped` | 灰色（`on_failure: "skip"` 触发，**不影响整轮成功**） |
   | 取消 | `cancelled` | 灰色/橙色（取消优先于失败：被取消的节点报 `cancelled` 而不是 `failed`） |
   | 未运行 | 无记录 | 中性灰 |

4. **三态齐备**：每个列表页必须有 加载中 / 空 / 错误（可重试）；每个空态必须给可点击的下一步。
5. **破坏性操作**：二次确认 + 明确后果文案；取消类操作不弹二次确认（运行中任务取消除外，需确认）。
6. **错误呈现**：后端错误经统一解包后展示 `message`；弱失败（返回 `{error}` 的 `tool.*` / `env.*`）必须显式检查。
7. **不做假定**：不要显示后端没有的字段（例如历史里的"进度百分比"、插件里的"加载失败原因"）。
