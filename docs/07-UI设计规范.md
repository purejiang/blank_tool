## 1. 信息架构与外壳（已决策，不可偏离）

- 四个一级模块 + 路由：工作流 `/workflows`（管理列表 + 二级编辑器 `/workflows/editor/:name?`）、任务 `/tasks`（默认 tab 任务列表 + `?tab=runs` 运行记录，二级任务编辑 `/tasks/editor/:name?`）、工具 `/tools`（**下辖三个页面**：工具 `/tools`、环境 `/tools/env`、插件 `/tools/plugins`；三页各自有标题/描述/工具栏/空态，靠页面头右侧区段切换跳转，**共用「工具」这一个导航项**——2026-09-28 决策，原"同页三 tab 面板"写法已废弃）、设置 `/settings`；`/` 重定向到 `/workflows`；侧边栏 4 项导航。
- 外壳：左侧窄边栏（顶部应用名 Blanks、4 个带图标导航项、底部主题切换）+ 右侧内容区（页面标题 + 描述头 + 内容）。
- 退役边界：PackagePage/DevicePage/APK 一键等 Android 专属页面全部退役，UI 中不得出现任何 Android 专属入口或措辞（Android 能力仅存在于用户导入的 examples/ 内容）。

## 2. 屏幕清单与功能要求（6 屏 + 状态）

本节是**功能元素下限**；逐屏的完整元素、字段、数据来源与状态以 [08-前端页面与功能清单](./08-前端页面与功能清单.md) 第 3 节为准（08 另含运行详情抽屉、工具/环境/插件三页、存储与历史保留策略、关于/诊断页，以及逐屏提示词）。

每屏列出**必须包含的功能元素**（设计可自由发挥视觉，功能元素不可删减）：

1. **工作流列表**：工具栏（新建工作流 主按钮 / 导入 / 导出 / 搜索）；工作流卡片网格（名称、一句话描述、节点数、最近更新、⋯ 菜单：编辑/复制/试运行/导出/删除）；空状态引导（导入示例工作流 / 新建工作流 两个按钮）。**卡片上没有"上次运行状态"徽章**（2026-09-28 决策：本页只回答"有哪些工作流"；运行状态属于运行记录，见 [08](./08-前端页面与功能清单.md) §3·S4）。
2. **工作流编辑器**：点阵网格画布，节点为卡片（图标/节点名/工具名），**横向链式连边（左→右，与节点左右端口一致）**，选中态高亮；顶栏（返回、可编辑工作流名、保存、试运行 主按钮）；**右侧常驻设置栏（320px）分「工作流 / 节点」两个 tab**：未选节点显示工作流信息（名称/版本/描述）+ 工作流级出入参，选中节点显示节点设置（分「基本 / 功能 / 参数 / 输出 / 行为」五区，类型化表单（文本、文件/目录选择行、下拉）+ 表达式绑定 chips 与「插入引用」候选）；节点区底部 删除节点；**画布多余出边的实时警告条（线性模型守卫，逐条列出连线），且该状态下保存被阻断**（完整契约见 [08](./08-前端页面与功能清单.md) S2「线性模型守卫」）。
3. **任务 · 任务列表**：工具栏（新建任务 主按钮 / 搜索 / 刷新）；任务行 = 任务名、一句话描述、**绑定的工作流名**（工作流被删时显示"工作流已不存在"警示）、入参项数、最近更新时间；行操作 运行 / 编辑 / 复制 / 删除 / 查看运行记录；空态（无任务 / 无工作流两种文案）。**任务是可持久化的执行配置（工作流 + 保存的入参），在第一次运行之前就存在**；本列表**不显示运行状态徽章**（状态属于运行记录）。
4. **任务 · 任务编辑**（`/tasks/editor/:name?`，二级页）：**表单是主体、工作流只占一行**——顶部返回 + 标题（+「删除」）；基本信息一行（任务名 / 描述）；**一行紧凑的工作流选择器**（可搜索下拉 + 节点数 + 「打开工作流」，**不做侧栏**）；按输入端口动态生成的表单**占满宽度**（两列网格；目录路径与 JSON 文本域整行；text/file-picker/folder-picker/bool/number/json/单选/多选）+ 底部操作条（工作目录（可选）+ 保存 / 保存并运行）；必填缺失时阻止保存并提示；改绑工作流时按端口名保留同名值、丢弃异名值前二次确认。**这是"任务的编辑"的唯一入口**。
5. **任务 · 运行记录**（`/tasks?tab=runs`）：筛选栏（名称搜索 + 任务筛选 + 状态下拉 全部/运行中/成功/失败/已取消）；行 = 状态徽章（运行中/成功/失败/已取消）、工作流名、**任务名**（为空显示"（试运行 / 一次性）"）、开始时间、耗时；可展开行 = 逐节点进度（✓/spinner/错误）+ 流式日志区；操作：取消 / 重新运行（有任务名 → 用该任务当前保存的入参）/ 打开运行目录 / 删除。运行记录**按上限自动裁剪**（`max_runs` / `max_bytes`，见 08 第 7 节缺口 #5）——**裁剪只影响运行记录，不影响任务定义**。
6. **工具 / 环境 / 插件（三个页面，一个导航项）**：三页各自有页面标题 + 描述 + 工具栏，靠页面头右侧的**区段切换**跳转，**不是同页 tab 面板**（2026-09-28 决策）。**工具**（`/tools`）：导入描述符 主按钮；工具卡片（图标、名称、来源徽章 内置/已导入/插件、版本、操作数、状态徽章 可用/不可用、**环境依赖徽章行**——声明了 `env_deps` 的工具必须点名它需要的环境与是否就绪，如「需要 Java · 未配置」，这是"不可用"的原因；⋯ 菜单：自定义路径/删除）；空状态引导（从 examples/ 导入工具描述符）。**环境**（`/tools/env`，承载 `env.*`）：未配置时的橙色告警带（"Java 未配置：依赖它的 N 个工具当前不可用"+ 跳工具页）；Java/Python/Node 行（检测路径、版本、状态徽章 已检测/未配置、**「被 N 个工具依赖」**、更改路径、⋯ 重置路径/删除且内置禁删）。**插件**（`/tools/plugins`，承载 `plugin.list/add/delete/reload`，详见 08 §3·S6.3）：模块名、kind 徽章 内置/原生、版本、加载状态（已加载/加载失败/未加载，失败行给红色错误文案）；内置禁删；**不显示环境依赖与工具归属**（后端无字段，见 08 §7-#18）。
7. **设置 + 关于**：分组表单——通用（**请求超时以秒显示、默认 300 秒、下限 30 秒**，一行灰色提示"修改后需重启应用生效"；系统通知 toggle 默认关）、外观（浅色/深色/自动 分段控件）、语言（简体中文/English）、**路径（只有两行可改：「工具链与运行时目录」`runtime` 与「后端目录」`server`，各带「浏览」按钮并注明"改后需重启后端"；`output`/`logs` 等数据目录是只读信息，放在「存储」分组）**、存储（用量 + 清除，含"输出目录包含已保存工作流、任务与运行历史"警示）；底部入口 诊断信息 / 关于。关于面板 = 通用运行时信息（应用/Electron/Node/Python 版本 + 后端健康状态徽章），不展示 bundled 工具版本。**设置页不再放「工具路径」卡片**（收敛到 `/tools`，只留跳转链接，见本文件第 2 节第 6 条与 [08 缺口 #19](./08-前端页面与功能清单.md)）。

- **通知约定**：任务完成/失败应用内 toast 始终开启；系统通知为设置开关、默认关（主进程 `enableNotifications` 默认值已随 WP4 改为 `false` 并带 v6→v7 迁移，见 [08](./08-前端页面与功能清单.md) 缺口 #15）。
- **主题**：浅色/深色/自动三模式，所有屏幕出两态（浅+深）。
- **任务模块口径（2026-09-28）**：`/tasks` 默认 tab 展示**任务定义**（工作流 + 保存的入参，首次运行前就存在），任务编辑在 `/tasks/editor/:name?`；运行记录（`?tab=runs`）是另一份数据（会被保留策略裁剪）。不要把"任务列表"设计成运行日志。
- **工具模块口径（2026-09-28）**：工具 / 环境 / 插件是**三个页面**（`/tools`、`/tools/env`、`/tools/plugins`），共用一个导航项；不要把三者画成一屏三个 tab 面板，也不要为了它们把侧边栏拆成 6 项。**环境是工具的前置**：工具卡片显示自己声明的 `env_deps` 状态，环境页显示"缺了会影响哪些工具"，两个方向都要有。

## 4. 设计 token 契约（维度与唯一来源）

**分工**：本节冻结的是**维度清单、命名与唯一来源**（工程约束，与设计稿无关）；**具体数值（色值、圆角弧度、间距阶、字号、字体）等首屏设计稿确认后一次性回填**——回填时机就是 §3 的「Edit Theme 锁定主题」那一步。提前把数值写进文档等于自由发挥视觉方向（§6 的交接约定明令禁止），并会造出第二份与设计稿打架的"权威"。

### 4.1 必须进 token 的维度

| 维度 | 覆盖范围 |
|---|---|
| 语义色（浅/深各一套） | 背景层次（body / sidebar / card / input / code / drop-zone）、描边、文本 4 级、状态色 4 类（成功 / 失败 / 运行中 / 已取消）×（主色 / hover / 弱背景 / 弱背景 hover） |
| 圆角 | 小 / 中 / 大 / 全圆四档；控件与容器共用同一套，不允许再出现"组件一套、Naive 另一套" |
| 间距 | xs / sm / md / lg / xl；页面骨架、卡片内距、列表行距都取自此阶 |
| 字号 · 字重 · 行高 | 阶 xs～3xl + 五档语义角色：页面标题 / 卡片标题 / 正文 / 辅助文本 / 等宽文本 |
| 字体栈 | 正文与等宽各一条，组件内不得另写 |
| 描边 · 阴影 · 焦点环 | 卡片 / 浮层 / 焦点态三档 |
| 控件高度与密度 | 按钮 / 输入 / 表格行的高度与内距（决定"信息密度高"能否成立） |
| 动效 | 时长（fast / normal）+ 缓动曲线，含 `prefers-reduced-motion` 的关闭策略 |

### 4.2 命名与唯一来源（现在冻结）

- **值清单与操作手册**：现有色板与分级的实况全表、分级缺口、改颜色/圆角/字体的步骤与验证命令见 [design.md](./design.md)——本文档只定契约（维度、唯一来源、护栏、回填时机），不复述具体数值。
- **唯一来源**：`src/renderer/theme/tokens.ts`（TS 常量，浅深两组 + 颜色以外的维度）。
- **生成产物**（头部标注 generated，禁止手改）：`src/renderer/assets/styles/themes.css` 的 `--app-*`。`src/renderer/theme/overrides.ts` 里结构性覆盖（组件级 micro 调整）可以手写，但**其中所有颜色与圆角值必须从 token 取值**，不得写字面量（如 `'8px'`），由 §4.4 的 parity 测试锁住。
- **前缀统一到 `--app-*`**，颜色以外的维度（圆角 / 间距 / 字号 / 动效）一并纳入该前缀族。`main.css` `:root` 里那套 Bootstrap 风格变量（`--primary-color: #007bff`、`--bg-primary` …）**退役**：它们没有深色变体、也不在 `[data-theme]` 选择器内，切深色不跟随，且与 `--app-green` 主色冲突。

### 4.3 现状差距（T24 清理项，2026-09-21 核实）

1. `theme/overrides.ts` 手抄了 `themes.css` 的整份色板（浅深各一份），并 6 次硬编码 `borderRadius: '8px'`。
2. `naive-overrides.css` 第 4 行硬编码 `border-radius: 8px`。
3. 5 个 `.vue` 里共 10 处硬编码主色 `#22C55E`（`LoadingScreen` / `AboutPage` / `UpdateDialog` / `SettingsPage` / `ToolsPage`）。
4. `App.vue` 侧边栏品牌字硬编码 `font-family: Inter, sans-serif`。
5. 圆角同时存在三个值：`--border-radius`（6px）、Naive 的 `8px`、`components.css` 的 `20px`。
6. `components.css` 引用了两个全仓未定义的变量（`--primary-color-light`、`--transition-normal`），相关声明实际不生效。
7. 遗留 `components.css` 的 29 个类在当前 `.vue` 里已无有效引用（唯一同名的 `.section-header` 被各视图的 scoped 规则遮蔽）→ 评估随 T24 删除；`main.css` 需逐类核对（含 `.m-*` / `.p-*` 工具类）。

### 4.4 护栏（新增测试，与 i18n 的 locale 护栏同型）

- **三方 parity**：`tokens.ts` ↔ 生成的 `themes.css` ↔ Naive 覆盖值三者一致，任一漂移即失败。
- **裸值扫描**：`.vue` 与非生成 CSS 里出现 `#hex`、`border-radius: Npx`、`font-family:`、`box-shadow:` 即失败（白名单仅限生成产物）。
- **两态覆盖**：每个 token 在浅色与深色下都有定义（缺一即失败）。

> `dev` 分支已有可搬的实现：`src/renderer/theme/tokens.ts`、`scripts/generate-theme-css.mjs`、`tests/unit/theme/tokens-css-parity.test.ts`、`tests/unit/theme/themeOverrides.test.ts`（当前 `workflow` 分支均不存在）。
