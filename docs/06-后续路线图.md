# 06 后续路线图

本文件记录**已确认延后**的功能项：当前不做，但保留设计预留与演进方向。每一项给出简述、价值与大致前置依赖，供排期决策时按优先级取用。

> 与 [05-分期开发计划](./05-分期开发计划.md) 的关系：05 是已排期的近期工作，本文件是明确的"以后再说"清单。其中标注"schema 已预留"的项，当前实现会保证兼容性，未来接入时不需要迁移存量数据。

## 一、DAG 条件分支

- **简述**：支持 `if/else` 走向，节点按 `condition` 表达式选择后续节点。
- **现状**：schema 已预留 `condition` / `on_success` / `edges` 字段（见 `cli/app/workflow/definition.py` 的 `WorkflowNode` 与 `WorkflowDefinition`），但引擎只做线性执行：带 `condition` 的节点会抛 `NotImplementedError`，`edges` 非空会校验失败。
- **价值**：解锁"某步失败才走修复分支"、"按环境选择打包流程"等真实分支场景，是工作流可用性的主要短板。
- **前置依赖**：表达式引擎（`cli/app/workflow/expression.py`）需支持 `condition` 求值；序列化器（`src/renderer/components/workflow/serializer.ts`）需处理多出边；引擎需从"单入口单链"改为"入口集合 + 后继求值"。

## 二、DAG 并行执行

- **简述**：多个无依赖的节点同时执行，而不是线性排队。
- **现状**：引擎按 `node.next` 单链顺序执行；`WorkflowDefinition` 的 `edges` 字段已为 DAG 预留。
- **价值**：下载多个 APK、并行反编译等场景可显著缩短总耗时。
- **前置依赖**：DAG 执行模型（依赖图拓扑排序 + 完成计数）；`TaskManager` 取消语义需要覆盖并发节点；节点级流式事件需带并发上下文（如 `node_id` 已具备，需保证线程安全）。

## 三、动态参数数据源绑定

- **简述**：入参下拉的选项来自动态数据源，例如"当前 ADB 设备列表"、"签名配置列表"、"某目录下的文件列表"。
- **现状**：**访谈确认暂不需要**。当前约定是：能作为入参传递的数据就直接传（例如设备序列号由任务页下拉静态提供，或由用户在表单里选）。`options` 字段目前为静态字符串列表（规划中见 Phase 1）。
- **价值**：让"设备选择""签名选择"等高频操作免手输，减少出错。
- **前置依赖**：Phase 1 的 `options` / `multi` 入参模型；若未来需要，再扩展为"数据源引用"（`options_from: "adb.devices"` 之类），并让渲染层注册数据源解析器。

## 四、借鉴 n8n / dify 的编辑与运维能力（延后）

以下能力在同类编排产品中常见，本版本明确延后，按价值排序：

| 项 | 简述 | 价值 | 大致前置依赖 |
|---|---|---|---|
| 运行历史 / 执行记录 | 每次工作流运行落库：入参快照、逐节点结果、耗时、错误，支持回看、复跑、按节点排查 | 排查"上次为什么失败"、复现问题、审计 | Phase 3 任务闭环落地后；新增执行记录存储与列表页 |
| 画布编辑体验 | 撤销/重做、快捷键、多选、复制粘贴、自动布局、便签 | 长工作流编辑效率与容错 | vue-flow 已内置部分能力，需封装成编辑器功能层 |
| 增强错误处理 | 每节点超时、指数退避重试、失败走错误分支输出 | 网络类节点（下载/安装）更稳 | 引擎 `on_failure` 已支持 `retry:N`，需扩展超时与退避参数 |
| 工作流版本 / 启停 / 标签 / 搜索 | 模板带版本、`active` 开关、标签过滤、按名称搜索 | 模板多了以后的管理体验 | Phase 2 工作流模块落地后；`template.*` handler 扩展元数据 |

## 五、更远期的设想

- **触发器**：目录监听（新 APK 落盘自动跑流程）、设备连接触发。价值是"零点击自动化"，但依赖文件监听与设备热插拔事件桥接，且当前任务模型是手动触发，跨度较大。
- **凭据 / 密钥保险库**：签名 keystore 密码等敏感信息的安全存储（当前存于应用配置）。价值是安全合规，前置依赖明确的威胁模型与加密方案，暂不排期。
- **官方领域包分发渠道**：领域内容外部化后（见 [05-分期开发计划](./05-分期开发计划.md#phase-1-基础模型)），提供官方分发的领域包（如 Android 工具包一键导入：描述符 + 二进制打包下载，或在线包索引），把"导入示例包"升级为"一键安装领域包"。**新增候选项**，尚未排期。
- **品牌化与设计系统化（候选项，已部分前置）**：本轮界面重设计的视觉体系以用户确认的 Google Stitch 设计稿为准（见 [05-分期开发计划](./05-分期开发计划.md#phase-2-工作流编辑与管理mvp)）；剩余候选为设计 token 化 / 组件规范统一 / 品牌深化，可单独排期，不阻塞功能演进。

## 六、插件系统

- **简述**：支持第三方以 `run(context, **params)` 形式的 `.py` 插件扩展能力。
- **现状**：地基已保留：`cli/plugins/` 自动发现机制 + `plugin_handler`；**UI 入口已移除**，作为路线图项暂不排期，未来重启时再做；当前 `cli/plugins/` 目录为空。
- **价值**：不侵入核心代码即可扩展 handler / 工具 / 工作流动作。
- **前置依赖**：无硬性前置；重启时需重新设计插件 UI 与生命周期管理。

## 决策原则

- 所有"已预留 schema"的延后项，都不以牺牲当前线性模式为代价：`condition` / `on_success` / `edges` 保持"存而不用"，现有工作流文件未来无需迁移。
- 排期时优先取"前置依赖最少、对已有用户收益最大"的项（如运行历史），再考虑 DAG 类结构性改动。
