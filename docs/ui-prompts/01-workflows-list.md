## 数据契约：id 才是身份（2026-09-30）

> 卡片**以存储 id（`wf-<12 位 hex>`）为 key**，工具栏「导出」下拉的 value、卡片 `⋯` 菜单的每个动作（编辑 / 复制 / 试运行 / 导出 / 重命名 / 删除）都按 **id** 定位。显示名**只是标签**：自由格式（`/`、`:`、emoji、中文都能用）、**可以重复**、只校验"非空"——它不是文件名、也不是身份。信息弹窗里另有一行**只读、可点击复制的工作流 id**（未保存的新工作流不显示）。

- **复制** = `workflow.load {id}` + `workflow.save`（**不带 id**）→ 后端分配一个**新 id**，原名那份原封不动。
- **重命名** = `workflow.save {id, name: 新名}`——**同一个 id + 新显示名**：文件名（id）不变，因此绑定的任务与子工作流引用都不会断，**既不删除旧文件、也不覆盖任何东西**。
- **撞名只是信息性提示**：新名字与另一个工作流同名时弹一条「已有同名工作流」（文案说明"工作流之间靠 id 区分，同名不会互相覆盖"），确认后照常保存。**不是**"覆盖同名工作流？"那种数据丢失确认——id 让两份工作流各自独立。
- **导出按 id 取定义**，导出内容是**不含 id 的纯 `WorkflowDefinition`**（可移植，文件名只影响用户自己看到的磁盘名）。
- **导入按显示名幂等**：已有恰好一条同名 → **覆盖它并保留原 id**（重导不产生副本）；没有同名 → 分配新 id。
