# ④ 任务编辑 `/tasks/editor/:name?`（二级页）

- **导航态**：任务（选中）；**二级页，从任务列表进入**，顶栏有返回箭头（与 `② 工作流编辑器` 同型）
- **前置**：先跑 [`00-shell.md`](./00-shell.md) 并在 Edit Theme 里锁定主题
- **功能元素来源**：[08 §3 · S3.2](../08-前端页面与功能清单.md)
- **本屏产出**：常规态（编辑既有任务）+ 未选择工作流时的表单区空态；浅 / 深两态
- **本屏的层级（重要）**：**主体是"入参的持久化"**——用户在这里要做的是"把这套参数名字与取值存下来，以后反复跑"。工作流只是**这套入参的 schema 来源 + 运行目标**，属于低频的一次性元信息，因此它只占**顶部一行紧凑选择器**，**不占侧栏**：表单必须拿到全宽（目录路径、JSON 多行、多选组、帮助文本都吃宽度）。
- **说明**：**这是"任务的编辑"的唯一入口**——`task.save` 落盘。它与 [`03-tasks-list.md`](./03-tasks-list.md) 是**两个页面**：列表只展示与操作，编辑在这一屏。

## 提示词（逐字粘贴，不要改写）

```text
沿用同一外壳，导航「任务」选中，这是二级页「任务编辑」（从任务列表进入，也用于新建任务）；
顶部是一个返回箭头与页面标题，标题右侧是「删除」文字按钮（编辑既有任务时才出现）。
从上到下四段，表单区占满整屏宽度：

1) 基本信息一行：任务名输入框（示例「每晚审计」）、一句话描述输入框（两者并排，任务名较窄）
2) 工作流一行（紧凑，只用一行高度，不要做成侧栏）：左侧小字标签「工作流」，紧跟一个带下拉箭头的
   选择框显示当前绑定的工作流名（示例 apk-audit），右边是灰色小字「12 个节点 · 发布前静态检查与报告生成」，
   最右侧一个次要按钮「打开工作流」
3) 入参表单（主体，占满宽度，两列网格排布）：
   - 目录选择行「目标目录 *」（占整行，等宽路径 + 浏览按钮）
   - 文本行「报告标题 *」（占整行）
   - 短字段并排：「最少匹配数 *」数字输入、「递归子目录」开关
   - 「输出格式 *」单选按钮组（3 个选项，占整行）
   - 「检查项 *」多选复选框组（4 个选项，两列排布，占整行）
   - 「额外参数（JSON）」等宽多行文本域（占整行）
   每个字段有名称、必填星号、下方灰色帮助文本
4) 底部固定操作条：「工作目录（可选）」路径行 + 浏览按钮（左侧），右侧两个按钮：次按钮「保存」、
   主按钮「保存并运行」
再出一版：还没有选择工作流时的表单区空态——表单区居中一行提示「先选择一个工作流，再填写它的入参」，
工作流那一行的选择框为空态样式（虚线边框）
```

> ⚠️ 三个不要：① **不要把工作流选择做成 320px 侧栏**（它是一次性元信息，不是主体；侧栏会压窄真正要填的表单）；② **不要把本屏做成"新建任务 = 直接执行"**——落点是**保存**（`task.save`），"保存并运行"是保存后再执行；③ **不要把本屏与任务列表合成一屏**（它们是两个路由：`/tasks` 与 `/tasks/editor/:name?`）。

## 交互补充（改绑工作流时的入参处理）

- 切换工作流会按**端口名**对齐已填值：同名端口的值保留，只存在于旧工作流的键**丢弃前先二次确认**（"切换工作流将移除 N 个不匹配的入参已填值"）；没有任何值会丢失时不打扰。
- 工作流被改名/删除（`workflow_exists = false`）时，选择器为空态 + 一行橙色提示，且「保存」被禁用，直到重新选择。
- 端口 `description` 作为字段帮助文本；`Port` 目前**没有 `default` 字段**（缺口 #10），因此没有"默认值预填"这回事，不要画出"已预填默认值"的样式。
