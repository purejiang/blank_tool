# ④ 任务编辑 `/tasks/editor/:ref?`（二级页）

- **导航态**：任务（选中）；**二级页，从任务列表进入**，顶栏有返回箭头（与 `② 工作流编辑器` 同型）
- **前置**：先跑 [`00-shell.md`](./00-shell.md) 并在 Edit Theme 里锁定主题
- **功能元素来源**：[08 §3 · S3.2](../08-前端页面与功能清单.md)
- **本屏产出**：常规态（编辑既有任务）+ 未选择工作流时的表单区空态；浅 / 深两态
- **本屏的层级（重要）**：**主体是"入参的持久化"**——用户在这里要做的是"把这套参数名字与取值存下来，以后反复跑"。工作流只是**这套入参的 schema 来源 + 运行目标**，属于低频的一次性元信息，因此它只占**顶部一行紧凑选择器**，**不占侧栏**：表单必须拿到全宽（目录路径、JSON 多行、多选组、帮助文本都吃宽度）。
- **说明**：**这是"任务的编辑"的唯一入口**——`task.save` 落盘。它与 [`03-tasks-list.md`](./03-tasks-list.md) 是**两个页面**：列表只展示与操作，编辑在这一屏。

## 数据契约：`:ref`、id 与绑定（2026-09-30）

- 路由是 **`/tasks/editor/:ref?`**：`:ref` 是任务的**存储 id**（`tk-<12 位 hex>`）；省略 = 新建。历史书签里的任务名后端仍能解析，旧链接不失效。
- **任务名是自由格式**：名字不再是文件名、也不再是身份（id 才是），所以只校验"非空"（`/`、`:`、emoji 都能用），**没有**"无分隔符、无 `..`"这类路径字符限制。
- **工作流选择框的 value 是 `workflow_id`**（存储 id），选项标签才是显示名（+ 节点数）：显示名可以重复，用名字当 value 会在改绑时认错目标；`task.get` 回 `workflow_id`，`task.save` 收 `workflow_id`（优先）或 `workflow`（显示名兜底）。
- **`task.save` 的参数**：`id`（有 = 覆盖这一个任务，无 = 新建并由后端分配 id）、`name`、`workflow_id`、`inputs`、`work_dir`、`description`。
- **运行 / 删除按 id**：`task.execute {id}`、`task.delete {id}`——名字可以重复，按名字定位会删/跑错那一个。**删除任务定义会连带删除该任务的运行产物（输出文件），运行记录保留。**

## 交互补充（改绑工作流时的入参处理）

- 切换工作流会按**端口名**对齐已填值：同名端口的值保留，只存在于旧工作流的键**丢弃前先二次确认**（"切换工作流将移除 N 个不匹配的入参已填值"）；没有任何值会丢失时不打扰。
- 工作流被**删除**（`workflow_exists = false`）时，选择器为空态 + 一行橙色提示，且「保存」被禁用，直到重新选择。⚠️ **改名不再触发这一态**（2026-09-30 改为 id 身份）：任务绑定的是 `workflow_id`，工作流改名后绑定照旧、显示名实时刷新。
- **工作目录留空 = 不指定**：运行期回落到**该轮的运行目录**（`$rundir` = `<output_dir>/runs/<run slug>`），不再回落到工作流库目录——不要画出"默认用工作流所在目录"的暗示。
- 端口 `description` 作为字段帮助文本；`Port` 目前**没有 `default` 字段**（缺口 #10），因此没有"默认值预填"这回事，不要画出"已预填默认值"的样式。
